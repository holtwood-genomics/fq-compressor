## 1. 结论

| 口径 | 字节 | 相对原始 FASTQ |
|---|---:|---:|
| 原始 R1 FASTQ | 99,934,080 | 1.000× |
| gzip -6（同一 FASTQ） | 21,097,162 | 4.737× |
| zstd -19（同一 FASTQ） | 16,463,409 | 6.070× |
| 当前 fast 路径 `fqc-sequential/v2` | 16,811,413 | 5.944× |
| CRAM（external GRCh38） | 5,929,273 | 16.854× |
| **`fqc-max-ref/v1`** | **4,547,935** | **21.974×** |

参考和 PAF 的口径必须分开：

- **external reference，不计入归档**：`99,934,080 / 4,547,935 = 21.974×`。这是本文件的主口径。
- **计入 PAF sidecar**：`99,934,080 / (4,547,935 + 49,043,976) = 1.865×`。PAF 只用于压缩，
  不进入归档，也不是解压依赖；把它计入时，单切片不再有优势。
- **计入完整 GRCh38 FASTA**：`99,934,080 / (4,547,935 + 3,273,481,150) = 0.0305×`。
  这是“小切片无法摊销 3.27 GB 参考”的算术后果，不是完整 30× WGS 的产品比例；完整 run
  必须另做参考计入/不计入两套数字，不能用本切片外推。

归档三路字节账：

| 流 | 字节 | 占归档 |
|---|---:|---:|
| ID（front-coded + zstd19） | 3,701 | 0.081% |
| quality（fqzcomp，12/12 块选中） | 2,181,008 | 47.956% |
| alignment（CIGAR + zstd19） | 2,352,120 | 51.718% |
| 容器/块头/checksum 等 | 11,106 | 0.244% |
| 合计 | **4,547,935** | 100% |

与合成 Phase 2.2 的结论不同：真实 WGS 的 ID 已经只剩 3.7 KB，**quality 与 alignment
几乎各占一半**。这意味着真实数据上的下一优先级不是继续优化 ID，而是分别评估质量上下文
模型和比对/编辑脚本编码。

## 4. 复现命令

### 4.1 R1 头部

```bash
OUT=/tmp/fqc-real-wgs-20261115/data
mkdir -p "$OUT"
curl -L --fail -r 0-21110783 \
  -o "$OUT/SRR14724532_1.head21m.fastq.gz" \
  https://ftp.sra.ebi.ac.uk/vol1/fastq/SRR147/032/SRR14724532/SRR14724532_1.fastq.gz
# 截断 gzip 流会报 gzip 的 unexpected EOF；只保留 298,974 条完整 4 行记录。
gzip -dc "$OUT/SRR14724532_1.head21m.fastq.gz" 2>/dev/null \
  | head -n 1195896 > "$OUT/SRR14724532_R1.head.fastq"
```

### 4.2 完整 hg38 与 minimap2

```bash
curl -L --fail -o "$OUT/hg38.fa.gz" \
  https://hgdownload.soe.ucsc.edu/goldenPath/hg38/bigZips/hg38.fa.gz
gzip -dc "$OUT/hg38.fa.gz" > "$OUT/hg38.fa"
MM=/tmp/fqc-real-wgs-20261115/tools/minimap2-2.31_x64-linux/minimap2
$MM -d "$OUT/hg38.mmi" "$OUT/hg38.fa" -t 12
$MM -x sr -c --secondary=no -t 12 "$OUT/hg38.mmi" \
  "$OUT/SRR14724532_R1.head.fastq" > "$OUT/SRR14724532_R1.head.paf"
```

### 4.3 归档与 round-trip

```bash
BIN=./build/clang-debug/tools/fqc_ref_archive
"$BIN" compress -i "$OUT/SRR14724532_R1.head.fastq" \
  --paf "$OUT/SRR14724532_R1.head.paf" -r "$OUT/hg38.fa" \
  -o "$OUT/SRR14724532_R1.head.fixed.fqmr" \
  --block-bases 4000000 --max-mismatches 16 -f
"$BIN" verify -i "$OUT/SRR14724532_R1.head.fixed.fqmr" -r "$OUT/hg38.fa"
"$BIN" decompress -i "$OUT/SRR14724532_R1.head.fixed.fqmr" -r "$OUT/hg38.fa" \
  -o "$OUT/SRR14724532_R1.head.fixed.restored.fastq" -f
cmp "$OUT/SRR14724532_R1.head.fastq" "$OUT/SRR14724532_R1.head.fixed.restored.fastq"
```

### 4.4 外部基线

```bash
gzip -6 -n -c "$OUT/SRR14724532_R1.head.fastq" > "$OUT/reads.gzip6.gz"
zstd -19 -q -f -o "$OUT/reads.zstd19.zst" "$OUT/SRR14724532_R1.head.fastq"
./build/clang-debug/src/fqc compress -i "$OUT/SRR14724532_R1.head.fastq" \
  -o "$OUT/SRR14724532_R1.head.fqc" --force

$MM -a -x sr --secondary=no -t 12 "$OUT/hg38.mmi" \
  "$OUT/SRR14724532_R1.head.fastq" > "$OUT/SRR14724532_R1.head.sam"
samtools sort -@ 4 -m 1G -o "$OUT/SRR14724532_R1.head.bam" \
  "$OUT/SRR14724532_R1.head.sam"
samtools view -C -T "$OUT/hg38.fa" -@ 4 \
  -o "$OUT/SRR14724532_R1.head.cram" "$OUT/SRR14724532_R1.head.bam"
samtools index "$OUT/SRR14724532_R1.head.cram"
```

`CRAM` 使用 external reference，包含 298,974 条 primary 记录（其中 298,179 条有
primary alignment，795 条未比对；另有 1,577 条 supplementary，被 `-F 0x900` 排除）。
它是 alignment container，不是 FASTQ 字节归档；
与 `fqmr` 的“归档更小”只能作为大小参考，不能当作功能等价或全面胜出。

## 6. 软屏蔽参考的大小写问题

第一次真实数据运行得到：

```text
mapped=109476 literal=189498 output=10258672 raw/archive=9.741x
```

根因不是 mapper 或 CIGAR，而是 UCSC hg38 的 soft-mask 小写碱基。首条 read 的参考切片
151 bp 中有 46 个 `a/c/g/t`；未归一化时大小写比较产生 46 个 mismatch（`--max-mismatches 16`
直接回退 literal），把参考转成大写后只有 1 个 mismatch。

修复位置：`tools/ref_archive/ref_archive.cpp` 的 `loadReference` 在读取 FASTA 时把
`a-z` 统一为大写；参考摘要和作用域仍绑定归一化后的 contig 序列。新增回归测试
`RefArchiveTest.NormalizesSoftMaskedReferenceCase`，验证小写参考仍能映射并 round-trip。
修复前结果保留为诊断记录，**不作为有效压缩比**。

## 7. 口径边界

- 这是 **R1 头部 298,974 reads**，不是完整 35× run，也不是 paired-end 联合压缩；
- 参考为完整 hg38 FASTA，但**external reference 不计入主口径**；PAF 也不计入；
- 质量是 NovaSeq 分箱质量（本切片 4 个符号，均值 Q35.68），不是全质量 HiSeq；
- 没有 `S/H/N/P`、长读 spliced alignment、BAM/CRAM sidecar、内置 mapper、参考嵌入、
  SHA-256、paired-end 联合、原子输出或内存上限；
- 没有同数据 ORA/Genozip/SPRING 复测；gzip/zstd/FQC/CRAM 只覆盖本文件列出的版本；
- `CRAM` 与 `fqmr` 的字节数不能直接解释为“同一功能下谁更优”；
- 完整 30× 人类 WGS 的参考摊销、重复区域和覆盖分布仍需独立验收。
