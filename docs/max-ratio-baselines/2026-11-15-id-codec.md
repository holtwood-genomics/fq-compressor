# 2026-11-15 ID 流自适应 front coding

- 状态：Phase 2.1 实验改进（`fqc-max-ref/v1` 的 `idCodec=2` 扩展，不是最终格式）
- 实现：`tools/ref_archive/ref_archive.cpp`
- 测试：`tests/tools/ref_archive_test.cpp`
- 主基线：[2026-11-15-ref-container.md](2026-11-15-ref-container.md)
- 设计：[docs/max-ratio-design.md](../max-ratio-design.md)
- 契约：[openspec/changes/2026-11-15-max-ratio-phase2-id-codec/design.md](../../openspec/changes/2026-11-15-max-ratio-phase2-id-codec/design.md)

参考原型的合成归档中，ID 流曾占 `fqc-max-ref/v1` 的 60% 左右（496,574 B / 827,688 B）。
真实 Illumina WGS 的 read ID 通常有稳定的 run/flowcell/lane/tile/x/y 结构，前缀重复度很高；
本实验先做一个不依赖 ID 语法的通用 **front coding**，再交给 zstd，并按块在 raw 与
front-coded 两种表示之间自适应选择。

## 1. 结论

1. **ID front coding 对结构化 ID 收益极大。** 本地 WGS 头部子集的 ID 流从 zstd19 的
   114,099 B 降到 1,085 B，约 **−99.0%**；NovaSeq 头部从 111,762 B 降到 1,105 B，
   约 **−99.0%**；HiSeq 25k 从 85,492 B 降到 83,641 B，约 **−2.2%**。
2. **随机 ID 不能强行 front code。** wgsim 原始 ID 的 raw zstd19 为 495,131 B，front-coded
   zstd19 为 545,494 B，反而大 **10.2%**；因此编码端必须按块选择较小者，不能全局强制。
3. **自适应选择保持旧归档兼容。** 原始 wgsim R1 重新压缩仍选择 raw codec，归档
   `827,688 B`、SHA-256 `23fe0fd1...`，与改动前逐字节一致。
4. **结构化 ID 合成实验把归档从 21.05× 推到 53.385× raw。** 该实验只把合成 R1 的 ID
   改成 Illumina 风格并同步改写 PAF query name；序列、参考、mapping、Q23 质量不变。
   它不是真实 WGS 结论，参考仍不计入归档。

## 2. 编码设计

`fqc-max-ref/v1` 的 block header 原本有 `idCodec` 字段和 4 字节尾部保留位。现在定义：

| 值 | 含义 |
|---|---|
| `1` | raw ID 逻辑流 + zstd19（原行为） |
| `2` | front-coded ID 逻辑流 + zstd19（新行为） |

raw 逻辑流：

```text
varint(recordCount)
per record: varint(idLen) + id + varint(commentLen) + comment
```

front-coded 逻辑流：

```text
varint(recordCount)
per record:
  varint(commonPrefixLen(id, previousId))
  varint(suffixLen)
  suffix bytes
  varint(commonPrefixLen(comment, previousComment))
  varint(suffixLen)
  suffix bytes
```

- 编码端同时生成 raw 与 front-coded 两种逻辑流，各自 zstd19，取压缩后更小者；
- `idCodec=1` 时尾部保留位写 0，保持旧归档字节布局；
- `idCodec=2` 时尾部 4 字节写 front-coded 逻辑流的未压缩长度 `codecIdsSize`；
- block checksum 仍覆盖**解码后的 raw ID 逻辑流**，因此完整性定义不随 codec 改变；
- 解码端先按 `codecIdsSize` 解压 front-coded 流，再重建 raw ID 流，校验其长度和 block
  checksum，最后交给原有 `decodeBlock`。

## 3. 真实数据 ID 探针

探针只读 FASTQ header，构造 raw 与 front-coded 逻辑流，分别 zstd19；不处理 sequence/
quality，也不写归档。复现脚本见 §6。本地探针环境：Python 3.12.2、`zstandard` 0.23.0，
zstd 单帧 level 19。

| 数据集 | records | raw 逻辑流 | front 逻辑流 | raw zstd19 | front zstd19 | 选择 | 变化 |
|---|---:|---:|---:|---:|---:|---|---:|
| HiSeq 25k R1 | 25,000 | 1,388,679 | 292,264 | 85,492 | **83,641** | front | **−2.2%** |
| WGS `SRR14724532` 头部 | 298,974 | 8,448,039 | 2,458,238 | 114,099 | **1,085** | front | **−99.0%** |
| NovaSeq `DRR174812` 头部 | 303,610 | 7,975,263 | 2,496,360 | 111,762 | **1,105** | front | **−99.0%** |
| wgsim 原始 ID | 50,000 | 2,223,238 | 1,862,016 | **495,131** | 545,494 | raw | front 反而 +10.2% |
| wgsim 结构化 ID | 50,000 | 2,500,003 | 255,699 | 30,827 | **230** | front | **−99.3%** |

关键解释：

- HiSeq 的 ID 也高度结构化，但当前 zstd19 已经能利用前缀冗余，所以只再省 2.2%；
  front coding 的收益集中在 WGS/NovaSeq 这类“长前缀 + 递增数字”的 ID。
- WGS/NovaSeq 的 1 KB 量级是 header-only probe，不等于完整归档；它说明 ID 不再是这两类
  数据的主要体积来源，后续应在真实 reference/PAF 归档中验证。
- 探针的 zstd 输出是单帧；实际归档按 4M bases 分块，每块独立选择并带 block header，
  因此归档中的 `ids=` 会略高于单帧数字。

## 4. 结构化 ID 合成归档实测

### 4.1 数据变换

在 Phase 2 原始合成 R1 上，把每条 read 的 ID 改成：

```text
A00123:1:H7YRLADXX:1:1101:{1000 + i/1000}:{2000 + i%1000}
```

comment 固定为 ` 1:N:0:ATCACG`；同时用原 ID → 新 ID 的映射改写 PAF 第一列。序列、
reference、PAF 坐标、质量值、mapped/literal 选择都不变。

| 文件 | 字节 | SHA-256 |
|---|---:|---|
| `r1.struct.fq` | 17,700,000 | `f53826400a4b69daaf8072a33d01fb2ecd37f3297599b2997628f0fbeee8baaa` |
| `r1.struct.paf` | 9,071,979 | `51ca888a30de942c792ffd5772fb0a4d59ea9e1339a47e8741dd6aca42488da7` |

**口径警告**：53.385× 是合成参考 + 3× 覆盖 + 恒定 Q23 + 人工结构化 ID 的机制验证。
它证明 ID codec 的效果，不是人类 30× WGS 的产品压缩比。参考 FASTA（5,071,439 B）不计入
归档；PAF 也不计入；真实分箱质量、重复区域、indel/clip、ID 分布都会改变结果。

## 5. 兼容性与边界

- `idCodec=1` 的旧归档仍可 `verify` / `decompress`；新增读取逻辑把尾部保留位 0 解释为
  “无 front-coded payload”。
- 反向不兼容：旧版工具只接受 `idCodec=1`，会拒绝 `idCodec=2` 的新归档；这是实验工具
  的一次单向扩展，不是双向兼容承诺。
- 新编码器对原始 wgsim R1 仍选择 raw codec，输出与改动前逐字节一致（同一 SHA）。
- `idCodec=2` 是同一 `fqc-max-ref/v1` magic 下的读取方向向后兼容扩展，不是新的正式
  格式版本；正式格式仍需要重新冻结 magic/version/header 布局。
- 当前 front coding 只处理“与上一条记录的公共前缀”，没有数字 token/delta、字段字典或
  跨块状态；这些仍是后续可做的 ID 压缩项。
- 仍只支持 canonical LF FASTQ；`+` 行、CRLF/混合行尾、空 read 未保真。

## 6. 复现

### 6.1 真实 ID 探针

需要 Python 3 与 `zstandard`；下面脚本写入 `/tmp/fqc_id_probe.py`：

```bash
cat > /tmp/fqc_id_probe.py <<'PY'
import sys, zstandard as zstd

def vu(n):
    out = bytearray()
    while n >= 0x80:
        out.append((n & 0x7f) | 0x80)
        n >>= 7
    out.append(n)
    return out

def headers(path):
    ids, comments = [], []
    with open(path, 'rb') as f:
        while True:
            h = f.readline()
            if not h:
                break
            f.readline(); f.readline(); f.readline()
            h = h.rstrip(b'\n')
            if h.endswith(b'\r'):
                h = h[:-1]
            if not h.startswith(b'@'):
                raise SystemExit('bad FASTQ header')
            h = h[1:]
            space = h.find(b' ')
            if space < 0:
                ids.append(h); comments.append(b'')
            else:
                ids.append(h[:space]); comments.append(h[space:])
    return ids, comments

def raw_stream(ids, comments):
    out = bytearray(vu(len(ids)))
    for a, b in zip(ids, comments):
        out += vu(len(a)) + a + vu(len(b)) + b
    return bytes(out)

def front_stream(ids, comments):
    out = bytearray(vu(len(ids)))
    pid = pcom = b''
    for a, b in zip(ids, comments):
        p = 0
        while p < min(len(pid), len(a)) and pid[p] == a[p]:
            p += 1
        out += vu(p) + vu(len(a) - p) + a[p:]
        p = 0
        while p < min(len(pcom), len(b)) and pcom[p] == b[p]:
            p += 1
        out += vu(p) + vu(len(b) - p) + b[p:]
        pid, pcom = a, b
    return bytes(out)

for path in sys.argv[1:]:
    ids, comments = headers(path)
    raw = raw_stream(ids, comments)
    front = front_stream(ids, comments)
    c = zstd.ZstdCompressor(level=19)
    print(path, 'records', len(ids), 'raw', len(raw), 'front', len(front),
          'raw_zstd19', len(c.compress(raw)), 'front_zstd19', len(c.compress(front)))
PY
```

运行：

```bash
python3 /tmp/fqc_id_probe.py \
  /tmp/fqc-exp/hiseq_R1.fastq \
  /tmp/fqc-exp/wgs/SRR14724532_R1.head.fastq \
  /tmp/fqc-exp/novaseq/DRR174812_R1.head.fastq \
  /tmp/fqc-ref-bench-20261115/r1.fq \
  /tmp/fqc-ref-bench-20261115/r1.struct.fq
```

### 6.2 结构化 ID 合成归档

先生成结构化 FASTQ/PAF（脚本以 `r1.fq` + `r1.paf` 为输入，使用原 ID 到新 ID 的映射）：

```bash
python3 - <<'PY'
from pathlib import Path
base = Path('/tmp/fqc-ref-bench-20261115')
idmap = {}
with (base / 'r1.fq').open('rb') as fin, (base / 'r1.struct.fq').open('wb') as fout:
    i = 0
    while True:
        h = fin.readline()
        if not h:
            break
        seq = fin.readline(); plus = fin.readline(); qual = fin.readline()
        old = h[1:].split(b' ', 1)[0].rstrip(b'\r\n').decode()
        new = f'A00123:1:H7YRLADXX:1:1101:{1000 + i // 1000}:{2000 + i % 1000}'
        idmap[old] = new
        fout.write(('@' + new + ' 1:N:0:ATCACG\n').encode())
        fout.write(seq); fout.write(plus); fout.write(qual)
        i += 1
with (base / 'r1.paf').open() as fin, (base / 'r1.struct.paf').open('w') as fout:
    for line in fin:
        if not line.strip():
            continue
        fields = line.rstrip('\n').split('\t')
        fields[0] = idmap[fields[0]]
        fout.write('\t'.join(fields) + '\n')
PY

BIN=./build/clang-debug/tools/fqc_ref_archive
BENCH=/tmp/fqc-ref-bench-20261115
"$BIN" compress -i "$BENCH/r1.struct.fq" --paf "$BENCH/r1.struct.paf" \
  -r "$BENCH/ref5m.fa" -o "$BENCH/r1.struct.fqmr" \
  --block-bases 4000000 --max-mismatches 16 -f
"$BIN" verify -i "$BENCH/r1.struct.fqmr" -r "$BENCH/ref5m.fa"
"$BIN" decompress -i "$BENCH/r1.struct.fqmr" -r "$BENCH/ref5m.fa" \
  -o "$BENCH/r1.struct.restored.fastq" -f
cmp "$BENCH/r1.struct.fq" "$BENCH/r1.struct.restored.fastq"
```

### 6.3 兼容性回归

```bash
"$BIN" compress -i "$BENCH/r1.fq" --paf "$BENCH/r1.paf" -r "$BENCH/ref5m.fa" \
  -o "$BENCH/r1.idcodec.fqmr" --block-bases 4000000 --max-mismatches 16 -f
cmp "$BENCH/r1.fqmr" "$BENCH/r1.idcodec.fqmr"
```
