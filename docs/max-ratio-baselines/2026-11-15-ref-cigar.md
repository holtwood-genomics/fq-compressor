## 3. 复现命令与输出

```bash
BIN=./build/clang-debug/tools/fqc_ref_archive
BENCH=/tmp/fqc-ref-bench-20261115

for mate in r1 r2; do
  "$BIN" compress -i "$BENCH/$mate.fq" --paf "$BENCH/$mate.paf" \
    -r "$BENCH/ref5m.fa" -o "$BENCH/$mate.cigar.fqmr" \
    --block-bases 4000000 --max-mismatches 16 -f
  "$BIN" verify -i "$BENCH/$mate.cigar.fqmr" -r "$BENCH/ref5m.fa"
  "$BIN" decompress -i "$BENCH/$mate.cigar.fqmr" -r "$BENCH/ref5m.fa" \
    -o "$BENCH/$mate.cigar.restored.fastq" -f
  cmp "$BENCH/$mate.fq" "$BENCH/$mate.cigar.restored.fastq"
done

sha256sum "$BENCH"/r{1,2}.cigar.fqmr
```

## 5. CIGAR 编码边界

本阶段支持 PAF `cg:Z:` 中的：

- `M`、`=`、`X`：参考与 query 同时消费；实际差异由参考和 read 重新计算，不信任 PAF
  的 `NM:i:`；
- `I`：query 多出的碱基，以 base code 存在 alignment 流；
- `D`：参考多出的碱基，不存序列；
- query 不覆盖整条 read 时，按 PAF `queryStart/queryEnd` 存原方向的左右 clip，clip
  也以 base code 存在 alignment 流。

不支持并回退 literal 的 CIGAR：`S/H/N/P`、空 CIGAR、操作数超过 256、长度为零或操作
消费量与 PAF 坐标不一致。`--max-mismatches` 仍只限制 `M/=/X` 内的替换数；indel 不是
替换，但仍受 CIGAR 操作数和坐标边界约束。负链以 reverse-complement 后的 aligned query
执行 CIGAR，写回时再反向还原；左右 clip 始终按原始 read 方向保存。

格式上新增 per-read flags bit3（`EXTENDED`），只在需要 clip 或 I/D 时出现；纯全长
`<len>M` 仍走 Phase 2 的旧布局，因此旧解码器可以读取旧归档，新解码器也可读取旧归档。
反向不兼容：旧工具不能读取带 bit3 的新归档，这是实验工具的单向扩展。

## 7. 不可外推与未完成

- 参考仍是 external FASTA，不计入归档；PAF 是压缩输入，不计入归档，也不是解压依赖；
- 质量恒定 Q23，真实质量分布下的归档结构与比例会不同；
- 没有真实人类 30× WGS；没有同数据 ORA/Genozip 对比；
- 没有 `S/H/N/P`、长读 spliced alignment、BAM/CRAM、内置 mapper、参考嵌入、SHA-256、
  跨 mate 质量/ID 联合、原子输出、内存上限或速度门禁；
- 本文件没有 paired 容器；后续 Phase 2.3 的 R1/R2 坐标 delta 见
  [2026-11-15-real-wgs-paired.md](2026-11-15-real-wgs-paired.md)；
- 只保证 canonical LF FASTQ 的字段级 round-trip；`+` 行内容、CRLF/混合行尾、空 read
  的原始字节保真仍未实现。
